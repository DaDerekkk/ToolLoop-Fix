# 评测口径 v0.1

本规范区分“工程已验证”与“研究待验证”。当前手工夹具、脚本策略和人工固定前缀均为 `synthetic_harness`；真实 Qwen 数据、正式划分及人工检测审查尚需另外完成。

## 1. 任务、可见性与预算
- 三域：订单查询、文件记录、处理任务；五类：normal、recoverable、retry_required、clarification、unrecoverable。
- 模型/运行时 guard 只获得用户请求、公开工具 schema、完整可见历史及实际用户补充。不得接收 category、可恢复标签、标准答案、未来状态或正确下一步。
- 隐藏环境负责故障、任务目标、可完成性与成功判定。评测器可读隐藏状态，但不得把评测反馈返回策略。
- 默认拟定上限为 12 次工具尝试；格式错误、未知工具、非法参数也计数。真实模型另设交互轮数和输出 token 上限，任一耗尽均非成功。
- 预算的 off-by-one 用测试锁定：最后一次允许调用可以取得证据，但若执行协议还要求最终回答而已无交互预算，则不能悄悄补发免费回答。
- 澄清任务必须预先规定用户模拟器回应规则；必要澄清不算提前放弃。若只有“提问正确”而没有补充信息后的续跑，只能报告澄清动作正确率，不能计完整任务成功。

## 2. 两层评测与配对
| 模式 | 起点 | 报告边界 |
|---|---|---|
| end_to_end | 同一个用户请求和初始环境 | 整体任务表现，模型会遭遇不同错误。 |
| fixed_failure_prefix | 完全相同的可见前缀、环境快照和剩余预算 | 条件恢复能力；不得与全程结果混算。 |

固定前缀必须保存来源（curated fixture 或自然模型轨迹 run/case/step）、原始状态哈希、可见历史哈希、已有调用数及剩余预算。每个策略从独立深拷贝恢复；候选试跑不得污染其他分支。随机故障需绑定事件/业务状态并固定 RNG 状态，而非按某策略的第 N 轮额外触发。

同一任务/种子上的方法逐一配对；合法重试与不可恢复场景也要保留。人工构造的失败点不能表述为模型自然故障发生率。

## 3. 循环检测与替代动作
### 判定原则
同工具出现两次不是充分条件。检测器版本中必须写明：动作规范化规则、观察窗口、重复阈值、公开错误类别、进展/新增信息判据、允许重试/轮询次数。

首版覆盖：同工具同参数；经工具特定规则确认的等价参数；短周期 A→B→A→B。不要全局 trim/改写所有参数而误把区分大小写的路径或有语义的空格视为相同。只有“已有可见反馈足以说明重复无益，且没有新增信息或合法重试条件”才能记无效循环。

合法重试必须遵守公开工具契约；后续成功不能反过来替当时行为补理由。观察型检测不修改行动；B2 guard 的拦截结果与模型自身行为分别报告。

### 标注与训练候选门禁
- 至少人工复核 200 段，覆盖检出、未检出、合法重试/轮询、真实进展和短周期；报告 TP/FP/FN/TN、抽样方式及分层数。非均匀抽样不可直接当总体错误率。
- 正式计算 precision/recall、FPR/FNR 时保留各自分母；零分母为 N/A。分歧裁决与检测阈值冻结记录不可省略。
- “第一次工具失败”未必是“第一次本可避免的错误”；训练决策点须定位已有足够反馈之后的错误动作。
- 每个 chosen/rejected 共用可见上下文和快照。检查工具合法性、信息来源、实际取得新信息/状态推进/可行恢复或正确终止；可有多个 chosen。单步可执行不等于已证明最终任务可恢复。
- 无充分证据的候选保留为 rejected_for_dataset/待审，不进入训练集。

## 4. 指标与分母
每个指标都输出 numerator、denominator、value；按方法、评测模式、业务域、任务类别分层。未实现/未采集不能填 0。

| 指标 | 分子 / 分母 |
|---|---|
| 任务完成率 | 证据与最终答案/环境状态均正确且未耗尽预算的次数 / 预先定义可完成任务次数。 |
| 错误恢复率 | fixed_failure_prefix 中可恢复任务续跑成功次数 / 该模式可恢复任务次数；与 retry_required 单独报告。 |
| 无效循环率 | 冻结检测器检出至少一次无效循环的轨迹数 / 全部被评测轨迹数；另列各循环类型。 |
| 必要重试成功率 | retry_required 中成功次数 / retry_required 次数。 |
| 提前放弃率 | 仍有合法完成路径却无必要地停止/求助的次数 / 可完成任务次数；必要澄清排除。 |
| 虚报成功率 | 声称完成但目标/证据未满足的次数 / 全部被评测轨迹数；可另报以“声称完成”为分母的条件率，名称需区分。 |
| 正确终止率 | unrecoverable 中如实解释并停止的次数 / unrecoverable 次数；不计进任务完成率分子或分母。 |
| 每成功任务成本 | 可完成任务的总成本（包含所有失败尝试）/ 成功次数；0 成功时报 N/A 并保留总成本。 |

成本至少报告工具尝试次数；模型阶段再报告输入/输出 token、耗时、设备时间和有依据的费用。模拟调用计数不是 GPU 成本或真实 API 成本。

读任务验证返回证据及答案一致，写任务检查环境目标状态；不能仅凭 `success=true` 或最终文字。报告原始 attempts 数，避免只统计成功轨迹导致成本偏低。

## 5. 数据隔离与统计
- 同流程只换实体 ID、同义文案或随机种子的变体属于同组。按流程模板、工具接口家族和故障组合分组后划分，不随机打散轨迹行。
- 跨域：两个业务域训练/开发，第三域整体留出；仍提供正常工具文档。外部 BFCL 子集需固定版本与许可证，禁止参与训练/调参。
- 开发夹具可以调代码，但不作为泛化证据。训练/验证/封闭测试 manifest 与哈希各自冻结，并检查组交叉。
- 正式计划每例 5 采样种子，报告均值及波动；不能用 best-of-5 当成功率。主方法和最强训练基线计划至少 3 训练种子。
- 差异按任务配对，置信区间按模板聚类；多个种子不是多个独立任务。先用预实验决定样本量与统计计划，再开正式测试。

## 6. 比较控制与验收
B0 原模型、B1 提示/历史优化、B2 运行时规则先完成；随后 B3 纠错 SFT、B4 单 token FTPO 风格、B5 一般动作 DPO、P 专项行动 DPO。所有推理共用工具、解析器、预算和采样；主 P 默认无外部 guard。B3/B4/P 尽量共享失败点与正例，匹配参数/调参预算并报告实际 token 与计算量；公平性不足单列限制。

提案目标待正式冻结：循环相对下降 ≥30%，相对最强不训练基线恢复 +5pp，正常与必要重试下降不超过 2pp。必须同时报告绝对差、配对区间、提前放弃、虚报和成本；相对改善在基线为 0 时 N/A。小样本烟测不能判定这些阈值达标。

如果只改提示/规则已足够，或 SFT 与专项 DPO 等效，结论应收缩到数据/工程价值；不能据此宣称新损失函数或训练方法优越。
