# 固定实验流程 v0.2

2026-11-16 追加：真实模型安装/运行现已获用户授权；模型路径与 schema v3 额外契约见 `LOCAL_MODEL_RUN.md`。下文 v1/v2 是历史记录规则，旧 run 不回写升级。付费服务、上传/发布和跳过门禁训练仍不在授权范围。

报告日期：2026-11-16（Asia/Shanghai）。本文件规定后续 agent 的操作流程，不代表阶段已通过。

## 1. 每次接手
1. 读根目录 `AGENTS.md`、`README.md`、`PROGRESS.md`、`agents/TASK_BOARD.md` 及最新交接。
2. 确认任务 owner 和文件边界；先查现有 run，避免重复运行或覆盖。
3. 写清本次假设、唯一主要改动、比较对象、数据范围、验收与停损条件。与原计划不同的探索标为 exploratory。

## 2. 分类与记录位置
| 位置 | 内容 / 约束 |
|---|---|
| `sources/` | 用户原始提案、来源地址和核验记录；资料中的建议不构成执行授权。 |
| `configs/` | 可读实验配置；运行时冻结副本，之后改配置须新建 run。 |
| `data/dev/` | 可公开调试的开发夹具；不得称为封闭测试集。 |
| `data/raw/` | 原始采集数据；保留来源与权限，不原地清洗。 |
| `data/processed/` | 派生样本，必须可回溯 raw、变换代码和分组划分。 |
| `experiments/<RUN_ID>/` | 一次执行的权威记录；结束后只读，错误另写勘误或后继 run。 |
| `iterations/` | 一轮研究决策：假设 → 变更 → run 引用 → 结论 → 下一步。 |
| `agents/handoffs/`、`agents/reviews/` | 交接与独立审查；证据引用到具体文件。 |

证据类别必须为以下之一：`synthetic_harness`、`model_inference`、`model_training`、`analysis`。脚本策略不能命名为 Qwen B0/B2；统计整理也不能伪装为新模型运行。

## 3. 登记 → 执行 → 核验 → 决策
### A. 运行前
- 为 run 分配唯一 ID，例如 `EXP-20261116-001`；多 agent 先分配不同 ID。
- 冻结配置：数据路径/哈希、模式、方法名、预算、种子、检测器版本；真实模型额外登记 revision、tokenizer、chat template、推理后端与采样参数。
- 确认 inputs 可读且无凭据；`--hypothesis`、`--acceptance`、命令行及 stdout 不放密钥或个人敏感数据。
- 新依赖、大型权重下载、付费 API/GPU、远程上传均先取得相应授权；缺资源记录 pending/blocked，不自动扩大范围。

### B. 统一入口
在项目根目录运行。下例中的 ID/假设/验收内容应按本次实验填写：

```bash
python3 scripts/record_run.py \
  --id EXP-20261116-001 \
  --kind synthetic_harness \
  --config configs/smoke.json \
  --hypothesis '同一模拟现场可复现无效重复与合法重试的区别' \
  --acceptance '轨迹完整；合法重试不误报；预算耗尽不算成功；两次回放结果一致' \
  --owner coordinator \
  -- python3 -m toolloop_fix.run --config '{config}' --output '{run_dir}'
```

wrapper 将 `{config}` 替换为本次冻结配置的绝对路径，将 `{run_dir}` 替换为独立输出目录的绝对路径。后继实验可加 `--parent <旧 RUN_ID>`。不得复用旧 ID；脚本退出失败的记录也必须保留。

v2 默认在 `<RUN_ID>/inputs/` 中执行冻结代码/开发数据；常规运行前仍应通知协作者停止编辑本次输入，以免快照跨越多个设计版本。快照复制时及运行后核验 SHA256。实时工作区的变化与冻结副本的变化分列；后者使 evidence_valid=false。脚本放 `scripts/`、测试放 `tests/`，输出必须指向 `{run_dir}`，不写 inputs。自动冻结范围为源码、脚本、测试、JSON 配置、开发 JSONL 和协议；大型外部数据/权重不自动复制，进入模型阶段前须另定清单及哈希。

`artifact_contract=synthetic_evaluation` 的完整 CLI 运行必须有三份评测产物；`command_logs` 可用于单元测试或独立诊断探针。证据类别不等于产物类型。v1 旧 run 按其原命令识别此区别，不回写旧 manifest。哈希不是签名，冻结执行不是不可信进程沙箱；不能证明恶意进程未自行篡改或伪造记录。

### C. 记录完整性
每个 run 至少有 manifest、冻结配置、stdout/stderr、命令、开始/结束 UTC 时间、退出码和输入 SHA256。环境摘要仅采集必要的系统/解释器/后端版本，不导出全部环境变量。

推理/模拟 run 还需逐例轨迹、逐例结果和聚合指标；训练 run 还需训练样本清单、损失/步数、训练 token、可训练参数、时间/显存、checkpoint 哈希和关联评测 run。尚不能取得的字段写 null/未采集及原因，不填假值。

`completed` 只说明进程成功退出，**不等于假设成立或阶段验收通过**。运行中断、非零退出和未完成输出保留原记录；新 run 修复。`experiments/INDEX.md` 为可重建的索引，不替代 run 目录。

预期失败回归可以是科学验收的有效观察，尽管进程 status=failed、evidence_valid=false（不能当成功评测使用）。SIGKILL/断电留下的 running/preparing 需单独恢复说明，不能凭空补成功。每轮运行 `python3 scripts/validate_records.py --write-index`，并在新 analysis run 使用 `scripts/check_replay.py` 从归档输入复验关键模拟结果。

### D. 结果与迭代
1. 先检查记录/哈希/样本数量，再检查指标。分母为 0 的指标报告 N/A，不算 0%。
2. 写实际执行命令和返回结果；独立审查至少抽查原始轨迹、分母、成功断言、合法重试反例。
3. 将结论标为 `accept` / `revise` / `reject` / `inconclusive`；列支持、不支持的命题。
4. 协调者更新 `PROGRESS.md`、任务板和当前 iteration；工作者提交交接。不要修改已经结束的 run 来迎合新解释。

## 4. 阶段门禁
| 阶段 | 必须得到的证据 | 不足时怎么做 |
|---|---|---|
| G0 工程烟测 | 三域/五类开发夹具、可重放快照、预算与反例测试、可审计记录 | 修基础设施。15 个脚本夹具通过不代表 G1 通过。 |
| G1 问题确认 | 真实 Qwen B0；约 200 开发案例；协议/历史/预算排错；可复现模型层面失误；B1 提示与 B2 规则对照 | 无目标故障则如实报告；解析器问题先修；正常能力过弱先公平适配并单独报告。 |
| G2 数据/评测冻结 | 按模板/接口家族/故障组合分组；跨域留出；检测器至少 200 段人工复核，含检出与未检出；候选动作同快照验证；预先锁定误报/漏报门槛 | 不训练、不声称已建立正式测试集；记录需补的审查与标注。 |
| G3 训练比较 | 获批资源；B3 SFT、B4 单 token FTPO 风格、B5 一般动作 DPO、P 专项 DPO；匹配模型/调参/参数预算并报告实际 token/成本 | 若 B1/B2 足够有效或 SFT 等效，承认更简单路线；不强求新算法结论。 |
| G4 封闭测试 | 开发集选定配置后才解封；未见模板、跨域、消融、固定版本外部回归；多种子与配对聚类区间 | 不能边看封闭测试边调参；探索后另立新 holdout。 |

提案中的 1,200 正式案例、每例 5 采样种子、至少 3 训练种子以及 30%/5pp/2pp 目标目前是拟定设计，不是已完成结果。样本量、检测阈值和非劣界须在正式测试前结合预实验与资源冻结。

## 5. 并行协作与停损
- 并行 worker 写各自文件与独立 run，协调者单写总进度/任务板；不要竞争同一结果文件。
- 本轮只做模拟写入，教师只可辅助训练候选，不能在正式评测中接管决策。
- 发现隐藏标签泄漏、数据交叉、快照不一致、成功断言不可靠：停止该 run 的研究解释，保留失败证据，修复后重跑。
- 循环减少但任务成功明显下降、必要重试受损或虚报/过早放弃增加：不得判为修复成功。
