# 用户工作约定（本次用户消息的持久化摘要）

来源：用户在 2026-11-16 聊天中提供的 AGENTS.md 指令；不是从磁盘发现的既有文件。以下保留其操作要求，供没有聊天历史的新 agent 使用。

## Think before editing
- 非平凡任务先一句话重述目标、声明重要假设；歧义影响实现时先问或列选项，不能默默猜。
- 有更简单安全方案就指出。简单一次性修改简短说明后做。

## Minimal, direct solutions
- 只做满足请求的最小完整修改；不加未请求功能、一次性抽象、配置框架或无关防御代码。
- 方案变大时停下来重新考虑简单路径；让资深工程师容易审查。

## Surgical changes
- 编辑前先读相关文件；不顺手重构、改名或格式化无关代码，匹配项目风格。
- 只清理本次改动新增的无用产物，不擅删历史死代码；无关缺陷单独报告。
- 每行修改都必须能解释与请求的关系。

## Goal-driven execution
- 多步任务简短计划：检查变更点 → 最小修改 → 定向验证 → 总结结果。
- Bug 尽量先复现和失败测试，再修，再做窄检查及必要的广检查。
- 功能明确预期、按现有模式测试；重构保持行为，尽量前后验证。
- 没运行的测试不能说通过；未验证需说明原因。

## Tool use / dependencies
- 定向查找优先，慢/破坏性/环境变更命令先说明必要性。
- 不随意安装依赖、改锁文件、迁移、删文件或重写大模块。
- 失败先读错误和修原因，不盲目重复。
- 新生产依赖先询问；优先已有库，不擅自升级包、换包管理器/构建工具。
- 无明确需要不引入网络、遥测、秘密或外部服务。

## Security and communication
- 不暴露、打印、提交或硬编码凭据；不弱化认证、授权、校验、日志及访问边界。
- 敏感数据避免入日志；不安全请求说明风险并提出安全替代。
- 收尾简洁包含：改了什么、实际验证、已知局限/后续风险。
