Executive Summary

项目摘要

一个 AI 能够正确调用一次接口，不代表它能够在接口出错后继续完成任务。

例如，模型查询订单时收到“编号无效”的反馈，却不断使用同一编号重新查询；或者读取文件失败后，不检查文件位置，而是一遍遍重复相同操作。这类系统虽然具备基本工具调用能力，但难以可靠地承担业务任务。

本项目以 Qwen3.5-0.8B 为基础模型，借鉴 Antidoom“定位错误开始的位置、针对性修复”的思想，将研究对象从文本重复扩展到工具执行中的无效重复。

核心研究问题：在有限工具和明确业务规则下，能否利用模型自身的失败记录，通过低成本专项训练，提高错误恢复率、减少无效调用，同时保留正常执行和合理重试能力？
让 Qwen3.5-0.8B 执行任务，记录完整调用轨迹
↓
检测第一次本可以避免的无效重复
↓
在相同环境快照中验证替代行动
↓
构建合理行动 vs. 错误行动偏好数据
↓
LoRA + 行动级偏好训练 / 单 Token 对照
↓
测试真实任务完成率、错误恢复率及副作用
项目的关键取舍

以“完整的下一步行动”作为主训练单位，将单 Token 的 FTPO 作为关键对照；保留 Antidoom 的局部修复思想，但不预先假设修正一个 Token 就足以解决工具决策问题。

说明：本文数据规模、实验配置和验收指标均为拟定方案，而非已取得的实验结果。

01研究背景：小模型为什么会陷入工具循环

1.1 用简单方式理解 Agent 和 Subagent

Agent 可以理解为能够使用软件工具、根据执行结果决定下一步的 AI 程序。工具可以是订单查询、文件搜索、数据库读取或任务状态检查接口。模型负责决定调用什么工具、填写什么参数、以及收到结果后如何继续。

本项目只研究边界明确的局部任务。小模型在其中承担简单步骤，可以作为 Subagent（子智能体），首版不需要搭建复杂的多智能体系统。

1.2 真正的问题不是重复，而是不会根据反馈调整行动

不合理重复

订单查询返回“订单编号无效”。

模型继续使用同一编号反复查询，直到耗尽预算。

合理重试

接口返回暂时超时，文档允许有限次数重试。

模型在重试预算内再次发起请求，成功后完成任务。

因此，禁止重复调用并不是目标。根据反馈选择正确动作才是核心：该重试时重试，该改参数时改参数，需要新信息时主动获取，确实无法继续时合理停止。

1.3 为什么选择 Qwen3.5-0.8B

Qwen3.5-0.8B 的官方模型资料提供了工具调用与 Agent 使用方式，意味着本项目并不是从零赋予其工具调用能力，也不以“官方没有考虑工具调用”为立项前提。项目要验证的是：它在原本能胜任的任务范围内，是否存在可复现、可通过专项训练改善的可靠性缺陷。

主实验统一采用非思考模式。思考模式下的文本重复风险可作为扩展研究，但不能与跨轮次工具调用循环混成一个指标。

02参考工作与研究定位

相关工作已经涉及文本循环、工具错误恢复和动作级偏好训练，因此“把 DPO 用在 Qwen 上”本身不构成充分的算法创新。

工作已有贡献本项目的借鉴与边界
Antidoom定位重复开始的 Token，进行局部偏好优化，并尽量减少原能力退化。借鉴错误定位与局部修复，但将检测对象扩展到工具行为。
Agentic-DPO利用同一上下文中的好/坏行动构造动作级偏好训练。行动级 DPO 并非本项目首次提出；研究重点是失败现场与可执行验证。
Fission-GRPO探索将执行错误转换为训练信号来提升恢复能力。本项目优先选择更轻量、可解释的离线修复方案。
BFCL / ToolSandbox在多轮和有状态工具环境中评估执行结果。除调用格式外，必须检验任务与环境状态。
Feedback That Backfires研究失败反馈的呈现方式与重复行为的关系。加入不训练、只优化提示词/历史呈现方式的强基线。
准确定位潜在创新

创新应从受控错误恢复数据、合法重试反例、局部偏好训练的有效性及可验证评测中寻找，而不是宣称提出全新的偏好损失函数。

03实验环境：先把问题复现准确

3.1 聚焦三个有限业务域

业务域示例任务重点能力
订单与商品查询查订单、查库存、获取配送状态参数修正、补全信息、无结果处理
文件与记录处理查找文件、读取内容、定位已移动文件状态变化、路径修复、避免无效重复
数据处理任务管理提交处理任务、查询运行状态、获取结果合理轮询、临时失败恢复、任务完成后停止

每项任务开放约 4–8 个相关工具，正常情况下主要需要 2–6 次调用。所有任务在可重置的模拟环境中执行，涉及写入的动作只修改模拟数据。

3.2 在训练前排除运行框架错误

  • 协议正确：工具输出与参数格式能够被可靠解析。
  • 历史完整：错误结果和已完成的动作不会被错误丢弃或截断。
  • 预算合理：正常完成任务所需步骤小于测试预算。
  • 配置可靠：先使用官方推荐的兼容方式，确定统一推理设置；不能用不合理的低温设置人为制造问题。

3.3 无效循环的判定

不能仅根据“相同工具出现两次”判断为循环。检测需结合动作等价性、工具反馈、任务状态、有无新增信息和合法重试条件。

首版重点检测：同工具同参数重复、等价参数重复，以及短周期的多工具循环（如 A → B → A → B）。复杂语义循环可作为扩展分析。

检测质量必须单独评估

检测规则与阈值在开发阶段冻结。人工复核至少 200 段包含检出和未检出的轨迹，计算误报、漏报，并重点检查是否错误拦截了合理重试或轮询。

04数据集：必须包括“应该重试”的反例

4.1 建议的正式测试集启动规模

1,200拟定测试案例数
5 类行为与故障类型
2 层固定错误点 + 完整执行
任务类型案例数正确行为防止的问题
正常任务400直接完成任务修复后正常能力下降
可恢复错误400修正参数、前置步骤或策略只会识别错误，不会恢复
必须合理重试200有限重试或轮询后完成把正常重试也禁止掉
需用户补充信息100询问必要信息后继续伪造参数或过度求助
当前无法完成100如实解释并停止无限重复或虚报成功

这一分布属于故障压力测试，不代表真实业务中各类故障的自然发生比例。无法完成的任务单独衡量正确终止率，不算入可完成任务的成功分母。

4.2 故障注入与信息边界

环境可控注入超时、前置条件缺失、路径失效、参数不完整等故障。故障应绑定到事件或业务状态，而不是机械地绑定固定轮数。

隐藏正确结果只能供评测器使用；模型和防护模块仅看到正常的工具文档与返回信息，不得获知“正确下一步”或“是否可恢复”的隐藏标签。

4.3 防止训练测试泄漏

按业务流程模板、工具接口家族和故障组合切分训练/验证/测试集。同一流程仅替换实体编号或同义描述的变体，必须放在同一数据集合中。

  • 未见模板：工具类型熟悉，但具体流程表达和错误组合不同。
  • 跨业务域：两个业务域训练，第三个业务域完整留出；测试时仍提供正常的工具说明。
  • 外部回归：使用固定版本的 BFCL 相关子集，且不将这些测试数据用于训练或调参。

4.4 训练规模以有效决策点为单位

训练不是按题目数量堆积，而是收集具有真实失败现场、且合理替代动作经过验证的决策点。建议先以约 1,000 个高质量决策点做方法验证，再扩展到 3,000–5,000，检验数据规模增加带来的增益。

05核心方法：基于失败现场的行动级偏好训练

5.1 从“第一次本可避免的错误”学习

第一次调用失败不一定代表模型决策错误。真正值得修复的是：模型已经得到足够的反馈，仍然采取明显无效的后续行动。

Rejected / 不希望的行动

文件路径已失效，工具返回“文件不存在”。

read_file(old_path)
→ File not found

read_file(old_path)
Chosen / 希望的行动

文件路径已失效，环境中另有文件搜索工具可用。

read_file(old_path)
→ File not found

search_file(filename)

5.2 在相同环境快照中验证替代动作

每次检测到无效重复后保存当时可见上下文及环境状态，尝试其他候选动作。候选动作可以来自程序规则、模型采样或教师模型，但必须经过验证：

  1. 工具存在且参数合法。
  2. 不使用模型尚不知道的隐藏信息。
  3. 确实取得新信息、推进状态、进入可行恢复路径，或在不能继续时正确终止。
  4. 如果多个动作都合理，允许多正例，不强迫唯一表述。

没有充分证据证明合理性的候选不进入训练集。教师只辅助产生训练候选，正式评估时不能由教师接管执行。

5.3 加入条件相反的对照样本

关键的防退化设计

同一工具调用可以在“暂时超时后”是合理的，在“确定参数无效后”是不合理的。训练数据要同时包含这两类样本，让模型学到依赖上下文的动作选择，而不是简单记住“不应该重复”。

5.4 主方法：完整行动偏好优化

主训练单位是“下一步完整行动”，例如工具名称与参数、必要澄清问题或最终回答。在相同错误上下文中，将合理行动作为 Chosen、无效行动作为 Rejected，使用现有 DPO 偏好训练。采用 LoRA 降低训练成本，并在训练目标中混入正常执行与合法重试行为，减少能力退化。

单 Token FTPO 是对照，不是默认结论。 一次工具调用的关键差异可能出现在后续参数而非起始 Token；如果压低通用的工具调用标记，甚至可能损害整个工具调用能力。

方法边界

首版只执行一轮“采集 → 验证 → 离线训练 → 评估”。不直接引入复杂在线强化学习；DPO 和 LoRA 都是已有方法，本项目创新不在于重新命名这些算法。

B4单 Token FTPO 风格对照局部 Token 修复是否足够？
B5基于专家轨迹的一般动作级 DPO专项失败挖掘是否优于普通行动偏好数据？

B3、B4 与 P 尽可能共享失败现场和经过验证的正例；训练方案匹配基础模型、可训练参数预算及调参预算，并报告实际训练 Token 与计算成本。推理阶段统一工具说明、解析器、预算和采样配置。

主方法不默认启用外部 LoopGuard。外部规则与修复模型的组合可以另作部署实验，但不能把规则拦截产生的收益算成模型真正学会恢复。

关键消融

  • 去掉合法重试对照：观察是否出现过早退出、必要重试能力下降。
  • 去掉正常行为保持训练：检查是否损害普通工具调用和结构化输出能力。

07评测框架：不能以少做事来换取少循环

7.1 两层评测

固定错误现场续跑：预先保存同一个失败前缀和环境状态，让全部模型从完全相同的位置继续。衡量真正的错误恢复能力。

从用户请求开始完整执行：观察模型是否真正完成任务，或发生错误、合理停止、耗尽调用预算。衡量整体业务价值。

主实验可设置工具调用上限 12 次，并同时限制交互轮数和输出长度。格式错误的调用尝试也占用预算。预算耗尽一律不算成功。

7.2 主指标

指标定义 / 统计口径避免的误判
任务完成率在可完成任务中实际完成目标的比例只减少循环，不完成任务
错误恢复率固定错误现场的可恢复任务中，续跑成功的比例不同模型遭遇不同错误的偏差
无效循环率按冻结规则识别的无效循环任务比例，并分类型报告只检查文本完全一致的调用
必要重试成功率必须重试或轮询的任务最终成功比例修复导致“害怕重试”
提前放弃率仍有合法完成路径却不必要地停止或求助的比例靠终止刷低循环率
虚报成功率未完成任务却报告已完成的比例只看最终文字判断成功
正确终止率当前无法完成任务中，如实说明并正确停止的比例把合理停止和逃避任务混为一谈
每成功任务的成本可完成任务的总消耗（含失败尝试）÷成功任务数只统计成功案例，隐藏失败成本

读操作需检查结果证据与答案；写操作需检查模拟环境的真实状态。程序断言和结构化检查为主，人工检查与语言模型裁判仅作辅助。

7.3 稳定性与统计检验

每个正式测试案例建议使用 5 个采样种子，报告平均性能及波动，不使用“五次中只要成功一次就算成功”的口径。主方法与最强训练基线至少用 3 个训练种子复核。

使用同一任务上的配对比较，并按任务模板聚类估计差值置信区间。同一题重复运行五次，不等于获得五个独立任务。1,200 个测试案例仅是启动规模，正式测试前应根据预实验方差和需要识别的差异确定样本量。

08验收目标与停损标准

8.1 建议的工程验收目标

维度拟定目标
无效循环相对原模型下降至少 30%，同时报告绝对变化
错误恢复相比开发集选出的最强不训练基线，争取提高至少 5 个百分点
正常能力正常任务完成率及必要重试成功率下降不超过预设的 2 个百分点容忍范围
行为副作用提前放弃及虚报成功不能成为减少循环的主要代偿
业务效率单位成功任务成本下降，或在可解释的成本增加下获得更高成功率

以上为实验前建议锁定的目标，不是已有结果。能力保持应结合差值置信区间评估，不能单凭点估计的微小下降作出确定结论。

8.2 什么结果才能支持研究结论

要说明专项失败现场训练确有价值，必须在合理匹配数据、模型及训练预算后，相比纠错 SFT 或一般动作级 DPO 有可复现的恢复收益，或在相同效果下具有更低的计算/数据成本。

结果不符合预期时如何解释

若普通 SFT 同样有效，应承认主要收益可能来自高质量错误数据；若提示词或规则已经解决绝大多数问题，应承认该场景更适合推理侧修复。若循环率降低但任务完成率明显下降，应判定修复失败。

8.3 暂停训练路线的条件

  • 主要失败源自工具解析、历史管理或运行框架，而不是模型本身：先修系统。
  • 正常任务能力太弱，以致无法研究错误恢复：先建立公平的共同格式适配起点，并单独报告其收益。
  • 合理设置下几乎不出现目标故障：记录结果，不使用不真实场景强行证明假设。

模型接入、工具协议检查、约 200 个开发案例、失败原因分类。

完成故障环境、轨迹检测、候选动作验证、训练/测试切分。

核心训练比较

训练 SFT、FTPO 风格单 Token、一般行动 DPO 与专项方法，完成开发集选择。

封闭测试与报告

资源安排

以单卡实验作为起点，优先考虑 24–48GB 显存级开发环境，但必须先通过实际短序列与小批量测试确定可行配置。训练聚焦语言和工具决策部分，不将视觉模块纳入首版目标。

记录模型与代码版本、聊天模板、随机种子、数据划分、训练 Token、GPU 时间、峰值显存和生成轨迹成本。教师模型只用于可选的训练候选生成，最终评测时不得接管执行。

最终交付

  1. 可复现评测环境：工具、故障注入、状态恢复、任务检查和固定错误现场测试。
  2. 可审计训练数据：每条样本可追溯到失败轨迹、环境快照、候选行动与验证结果。
  3. 修复模型与训练脚本：Qwen3.5-0.8B 的适配权重、配置和复现工具。
  4. 完整实验报告：说明何时有效、何时失败、是否误伤合法重试，以及收益来自何处。
Core Thesis

ToolLoop-Fix 研究如何利用经过执行验证的失败轨迹，对 Qwen3.5-0.8B 进行局部行动偏好训练，使其在限定工具任务中减少无效循环、提高恢复能力，并保留正常执行与必要重试。

项目真正要证明的是：一个小模型在出错以后，能不能仍然把该做的事情做完。
