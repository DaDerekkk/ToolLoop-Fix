## 1. 研究背景与核心痛点

### 1.1 轻量级 Agent 模型为什么容易“卡死在工具死循环里”？
在实际工具调用场景中，小参数模型（本课题基座：`Qwen/Qwen3.5-0.8B`，固定 revision `2fc06364715b967f1860aea9cf38778875588b17`）在遭遇工具错误后存在两难困境：
1. **不可重试故障下的死循环与乱猜**：当工具返回无效标识（`INVALID_IDENTIFIER`）、前置条件缺失（`PRECONDITION_REQUIRED`）或资源永久不可用（`RESOURCE_UNAVAILABLE`）时，模型往往反复重放相同错误调用（Adjacent Repeat `AA` 或非相邻短循环 `AB → A`），耗尽交互预算，甚至在未观察到有效证据时编造成功输出（`false_success`）。
2. **过度防错导致的“不敢重试 / 过早放弃”**：在面对瞬时故障（`TIMEOUT`）或异步状态（`PENDING`）时，如果靠提示词或负向抑制粗暴禁止重复调用，模型反而会在本该合法重试或轮询时直接拒答放弃。

### 1.2 现有非训练方案在未见模板上全部失灵
在本课题构建的独立未见模板验证上（100% 关闭或公平对照外部规则）：
- **修改解码参数无效（G1）**：纯贪心 `greedy_pp0` 与重复惩罚 `greedy_pp2` 在可恢复前缀上恢复率均为 `0/4`，纯贪心更在 3 个前缀上诱发长达 10–11 轮的 `ask_user` 预算耗尽循环。
- **提示工程 `B1` 失效**：在 G4 封闭集上，强提示 `B1` 端到端精确完成率跌至 `0/30 (0.0%)`，过早放弃率高达 `76.7% (23/30)`。
- **外部规则守卫 `B2` 治标不治本**：仅能拦截紧邻重复调用，在 G4 封闭集上仍有 `11.1% (4/36)` 非相邻循环逃逸，端到端精确完成率仅 `2/30 (6.7%)`，平均单次成功耗时高达 `50.00` 次尝试。

## 2. 严谨的五道阶段门禁与评测治理（G0 → G4）

为杜绝“看测试集调参”“模拟代替真实模型”“外部规则掩盖真实能力”等研究偏差，全项目通过 `123` 个独立归档实验（`0` 完整性错误）按五道门禁推进：

1. **G0（隔离评测基建）**：构建无第三方依赖确定性重放沙盒 `toolloop_fix/harness.py`（SHA256 全程不可变），模型仅接触公开请求、工具说明与可见历史，隐藏状态仅供评测器使用。
2. **G1（问题确证）**：5 种子采样 + 195 例（45 模板组）零泄漏分组开发池，排除单种子假象与模板泄露。
3. **G2（检测器冻结与数据治理）**：
   - 采用隔离双盲代理标定 + 用户授权三盲仲裁（`user_delegated_triple_blind_silver_adjudication_v1`，明确披露非纯人工手标金标；双盲语义一致 `95.78%` / `κ=0.9462`，循环一致 `100.00%` / `κ=1.0000`）。
   - 冻结 `loop_detector_v2`：总体精确率 **`100.00%`（162/162）**，总体召回率 **`98.78%`（162/164）**，**真实模型轨迹循环召回率由 `v1` 的 `79.38%` 跃升至 `97.94%`（`+18.56pp`）**，合法重试误报率 **`0.00%`（0/85）**。
4. **G3（多臂公平微调）**：严格零泄漏训练池（仅 `orders + files` 14 个模板组），6 套对照/消融数据集在 Colab NVIDIA L4 上用统一超参与步数训得 `10` 个 LoRA 适配器。
5. **G4（单次解封封闭测试与独立审计）**：在完全未见过的 `36` 个全新模板组（24 例域内 `orders+files` + 12 例**零样本跨域 `jobs`**）与 `18` 例固定失败前缀上单次解封评测，**所有训后模型强制关闭外部防循环守卫（`guard_blocked_proposals == 0`）**，最终通过零 ML 依赖纯 CPU 全量重放审计。

## 3. 方法设计：失败现场决策点数据工程 + 多臂公平对照

### 3.1 四类执行验证决策点（严格从域内训练池构造，N=400）
所有正负动作均在同一 `Environment` 快照下通过执行验证，彻底隔离测试模板、实体与 `jobs` 域：
1. **非可重试故障恢复**：识别无效/前置故障并切换合法替代工具或补齐前置条件。
2. **相反上下文合法重试/轮询**：遇到 `TIMEOUT` / `PENDING` 时执行合法重试与 `poll_job`，防止过度保守。
3. **不可恢复正确停止（`stop_task`）**：当任务确实不可完成时诚实止损，拒绝循环和编造成功。
4. **正常任务保持（`finish_task`）**：防止微调后模型在普通可用任务上过度拒答。

### 3.2 六个训练臂 + 三个未训练基线的公平对比矩阵
统一配置：纯 PyTorch LoRA（`rank=4, alpha=8.0, dropout=0.0`，文本主干 186 个线性层 / `2,705,664` 可训练参数，单权重仅 `~5.45 MB`，对称 `50` 优化步，基座权重 SHA256 全程零变更）。

| 组别 | 类别 | 训练数据与损失设计要点 | 科学对照目的 |
|---|---|---|---|
| `B0` / `B1` / `B2` | 未训练基线 | 原始模型 / 强恢复提示 / 运行时重复守卫 | 建立能力下界与外部守卫上限 |
| **`B3`** | **失败现场纠错 SFT** | 与 `P` 完全同源 `400` 决策点，completion-only NLL（纯正监督） | 剥离“数据本身”与“偏好负梯度”的归因 |
| `B4` | 单 Token FTPO 风格 | 同源 `400` 决策点，仅在首个分歧 token `k*` 加局部 DPO + 锚点 | 检验细粒度单 token 偏好惩罚的语法风险 |
| `B5` | 通用专家 DPO | `400` 条 **0% 错误历史**的干净专家偏好对 | 检验无失败现场数据的通用对齐能否防循环 |
| **`P`（ToolLoop-Fix）** | **完整动作级 DPO** | 失败现场全动作 DPO + 合法重试反例 + 正常保留（`sft_anchor=0.2`） | 检验提案主方法 |
| `P_no_retry` | 数据消融 1 | 去掉合法重试/轮询反例（`N=320`） | 检验合法重试样本的因果必要性 |
| `P_no_normal` | 数据消融 2 | 去掉正常任务保留样本（`N=320`） | 检验正常保留样本的因果必要性 |

*稳定性复验*：对核心对照 `B3` 与 `P` 追加 3 个独立训练种子（`101, 202, 303`），共 10 个 Colab L4 LoRA 适配器。

### 3.3 L4 训练显存突破（工程亮点）
`Qwen3.5` 的门控线性注意力（`chunk_gated_delta_rule`）在默认反向传播下会保存 `6,036` 个 FP32 中间张量（峰值 `~45 GiB`，触发 L4 `22 GiB` OOM）。通过**非重入激活检查点 + 完成窗口 `lm_head` 切片 + SDPA + `fla-core==0.6.0` Triton 内核**，将激活显存压降约 **45 倍**（至 `~1.0 GiB`，实测峰值仅 `3.57–5.54 GiB`，数值偏差 `0.000e+00`），分 3 个短波次安全完成全部 10 个适配器训练并彻底释放云端会话。

## 5. 深度机理分析：为什么是 `B3 > P >> B5 / B4 / B2 / B1 / B0`？

1. **决定性因果因子是“失败现场决策点数据”，而非通用对齐（`B3, P >> B5`）**：
   `B5`（无错误历史专家 DPO）虽然能把 `normal` 任务拉到 `100%`，但可恢复故障仍为 **`0/12 (0.0%)`**、正确停止为 **`0/6 (0.0%)`**，无效循环更恶化至 **`36.1%`**（差于未训练 `B0` 的 `22.2%`），直接证伪“普通工具微调能顺便学会避循环”。
2. **数据配比两翼缺一不可（`P >> P_no_retry, P_no_normal`）**：
   去掉合法重试使 `retry_required` 直接归零（`0/6`）；去掉正常保留使模型在正常任务上崩溃为过度拒答（`73.3%` 过早放弃、`0/30` 完成）。
3. **负偏好梯度破坏小模型结构化 XML 语法的实证链（`B4 → P → B3`）**：
   - `B4` 将负梯度集中在首个分歧 token，直接摧毁 XML 闭合格式（如产生 `<-get_order>`，G4 解析错误轮率 **`72.0%`**）。
   - `P` 将 DPO 负梯度分摊到完整动作并加 `sft_anchor=0.2`，虽在 `s101` 表现优良，但正负动作共享大量 `<tool_call>` 结构标签，在 `0.8B` 参数容量下依然诱发跨种子语法脆性（`10.5%–43.2%` 解析错误）。
   - `B3` 对执行验证纠错动作施加纯正样本最大似然监督，**无负梯度语法推力**，解析错误压在 **`3.4%–5.5%`**，兼得零循环、满分固定前缀恢复与最强零样本跨域迁移（较 `B0` 降本 **`11.5 倍`**）。

## 6. 独立审计、诚实局限与工程启示

- **零偏差独立纯 CPU 审计（`EXP-20261120-REVIEW-009R2`）**：不导入任何 ML 库，逐轮确定性重放 ITER-009 全部 **32 个模型推理实验 / `846` 个 episode / `4,029` 次真实生成**，**`0` 处偏差、`0` 隐藏状态提示泄露**，全部 `10/10` 云端 LoRA 适配器哈希验证通过，核心评测环境 `harness.py` SHA256 全程未改，全仓 `326/326` 单元测试通过。
- **诚实局限**：单一基座规模（`Qwen3.5-0.8B`）、受限预算下的中等样本量（`N=400` 训练 / `36` 模板组封闭评测）以及 G2 阶段采用三盲代理银标仲裁而非纯人类专家精标。
- **对轻量级 Agent 训练的实践启示**：在 `≤1B` 严格结构化工具调用模型上，**构建高质量“失败现场—合法重试—正确停止—正常保留”四象限执行验证数据集 + 纠错 SFT** 是性价比最高、最稳定的首选方案；若需引入偏好优化，建议采用 SFT 冷启动 + 更低学习率 / 更强 KL 约束的保守方案。
