# NotebookLM Slide Deck 生成与迭代指南

## 一、如何导入 NotebookLM 生成初版 PPT

1. 打开 NotebookLM，新建一个 Notebook（建议命名：`ToolLoop-Fix 实验汇报`）。
2. 点击 **Add sources（添加来源）** → 上传以下核心文件（建议至少上传前 2 个，避免冗余干扰）：
   - **必传主源（最精炼、无噪声）**：`docs/presentation/NOTEBOOKLM_PPT_SOURCE.md`
   - **可选补充详细源**：`FINAL_REPORT.md`、`experiments/EXP-20261120-105R1/g3_g4_comparison.md`
3. 在右侧 **Studio** 面板选择 **Slide Deck（演示文稿）** → 点击定制铅笔图标，粘贴下方“定制提示词”。

## 二、可直接粘贴进 NotebookLM Slide Deck 的定制提示词

```text
请严格基于我提供的来源文档，制作一份 12 页的中文学术研究与工程汇报 PPT（目标受众：LLM/Agent 课程导师与工程评审），风格克制、图表化、数据零幻觉。

硬性内容与排版约束：
1. 每页一个清晰核心结论作为主标题（Assertion-Evidence 标题），正文只列关键指标与结构化对比，不要整段大块文字。
2. 所有数值必须严格与来源文档一致，严禁四舍五入捏造新数字或把“B3 > P”写反！
3. 必须忠实呈现本课题最核心的科学反转（Proposal §8.2 诚实结论）：
   - P（ToolLoop-Fix 动作 DPO，s101）已大幅成功：G4 封闭 E2E 精确完成从 10.0% → 70.0%，循环率 22.2% → 2.8%（相对降 87.5%），成本降 5.7 倍；

   - 机制链条为“B4 (72.0% 解析错误) → P (10.5%–43.2% 解析错误) → B3 (3.4%–5.5% 解析错误)”，证明决定性因果因子是执行验证失败现场数据，而非离线 DPO 负梯度。
4. 建议 12 页结构：
   - P1 封面：标题 + 核心副标题（0.8B 模型 2.71M 参数实现零循环工具恢复）
   - P2 问题定义：小模型遇到不可重试故障的两难困境（死循环 vs 不敢重试）

   - P7 云端工程突破：解决 Qwen3.5 线性注意力 45GiB OOM（非重入检查点 + lm_head 切片 + fla-core Triton）训完 10 个 LoRA
```

## 三、拿到 NotebookLM 初版后的“迭代精修 5 点核查表”

生成第一版幻灯片后，用下面 5 条问题回问 NotebookLM 或微调每页文案，即完成高质量“迭代一波”：

1. **数字一致性核对**：检查是否把 `B0 (10.0%) / B1 (0.0%) / B2 (6.7%) / B4 (10.0%) / B5 (43.3%) / P_s101 (70.0%) / P_3seed (61.1%) / B3_3seed (96.7%)` 写准确；检查 `B4 解析错误 72.0%` 与 `B5 循环率 36.1%` 没混淆。
2. **科学诚信与加分点核对**：确认 PPT 没有为了迎合 DPO 而掩盖 `B3 > P`（`P - B3 = -35.6pp`），反而把它作为最具洞察力的核心发现单独成页。
3. **概念边界核对**：确认没有把 `B2` 的循环率 `11.1%` 归功于模型训练（除 `B2` 外全部臂强制 `guard_blocked_proposals == 0`），也没有把 G2 三盲代理银标误写成“纯人类专家手工精标”。
4. **视觉密度优化**：若某页文字超过 60 字，追问 NotebookLM：“请把第 X 页改写成 1 句核心结论 + 1 张 3 列表格 + 2 条简短洞察要点，并生成配套口头讲稿（每页 45 秒）。”
5. **导出留档**：从 NotebookLM 导出 PDF / PPTX（或导入 Google Slides 微调版式）后，可保存到 `docs/presentation/` 再一并推上 GitHub（建议导出前控制单文件体积 `< 25 MB`）。
